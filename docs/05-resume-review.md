# 05 · 简历评估维度

> 用途有两个：**改自己的简历**，或**批量看别人的简历**（招聘侧）。两件事用的是同一套判据。

---

## 一、先分清两种评估

| 类型 | 问的问题 | 适用 |
|---|---|---|
| **匹配度评估** | 这个人适合这个岗位吗 | 有明确 JD 的招聘 |
| **质量评估** | 这份简历本身写得好不好 | 建人才库 / 改自己的简历 |

匹配度随 JD 变，质量评估相对稳定。**建议先做质量评估**：质量不过关的简历，匹配度再高也读不下去。

---

## 二、五维质量评分

| 维度 | 看什么 | 差 | 好 |
|---|---|---|---|
| **完整性** | 关键字段是否齐（时间线、学历、联系方式、期望） | 缺时间、跳段、只有公司名没有职责 | 时间连续、每段有起止、职责与成果分明 |
| **职业轨迹** | 是否在往上走 | 三年换四份、职级原地踏步、方向漂移 | 有主线、每跳有明确理由、职责范围递增 |
| **成果呈现** | 有没有"结果" | 只写"负责 XX 工作" | 写"做了什么 + 结果如何"，带数字 |
| **能力深度** | 是否只停留在执行层 | 全是"参与""协助""配合" | 有主导、有方案、有取舍 |
| **表达结构** | 是否 10 秒能读完重点 | 大段文字、无分段、术语堆砌 | 一页内、模块清晰、动词开头 |

打分建议 1–5 分制，总分 25。**低于 15 分的简历，不必进入匹配度环节。**

---

## 三、结构化提取字段

批量处理时先提取，再评分。字段定义要**允许"未知"**，不许推测：

| 字段 | 提取规则 |
|---|---|
| 姓名 | 中文名优先 |
| 最高学历 / 院校 / 专业 | 标准化学历：博士 / 硕士 / 本科 / 大专 / 中专及以下 |
| 毕业时间 | `YYYY.MM`；在读写"预计 YYYY.MM" |
| 工作年限 | 从第一份全职算起（不含实习），精确到年 |
| 当前/最近公司、岗位 | 最近一段全职 |
| 期望城市 / 期望薪资 | 没写就填"未知" |
| 联系方式 | 手机建议脱敏保存（138****1234） |

> 用 LLM 批量提取时，**提示词里明确写"未提供填未知，禁止推测"**，否则模型会补全不存在的字段。

---

## 四、成果怎么写才算数

判断一条经历是"成果"还是"职责"，看三个要素：

| 要素 | 反例 | 正例 |
|---|---|---|
| 动作 | 负责考勤管理 | 重建考勤审核流程 |
| 对象/范围 | — | 覆盖 12 个分公司、3000 人 |
| 结果 | — | 月均差错从 40 条降到 3 条，节省 2 人天/月 |

三者缺一，这条经历就只是"岗位说明书"。

**没有数字怎么办**：用相对量（"从 0 到 1""首次""缩短一半"）、用范围（"覆盖 5 个部门"）、用对比（"较上一版减少 30% 返工"）。都没有，就说明这段确实没做出可衡量的东西——那就换一段写。

---

## 五、批量评估的工程做法

```
简历文件（PDF/DOCX）
  → 转图片或纯文本
  → 模型：提取字段 + 分类 + 五维打分
  → SQLite 记录状态（断点续传）
  → Excel 汇总
```

三条经验：

1. **状态表必须有**：几百份简历跑一半断了，没有状态表就得重跑。
2. **评分与提取分开两轮**：一轮让模型只做提取（准确率高），一轮只做评分（口径一致）。
3. **抽样人工复核**：随机抽 10 份对一遍，确认模型没有系统性偏差（比如对某类学校/公司有偏好）。

---

## 六、给自己的简历做一次体检

按顺序问五个问题：

1. 10 秒内能看出我是做什么的吗？（不能 → 改标题与摘要）
2. 每段经历有结果吗？（没有 → 补数字或换段落）
3. 时间线有断点吗？（有 → 补一句说明，别让人猜）
4. 有没有和目标岗位完全无关的内容占版面？（有 → 删）
5. 我用的词，对方的 HR 看得懂吗？（看不懂 → 换成 JD 里的词）

五问全过，再去做匹配度优化。
